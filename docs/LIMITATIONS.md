# Known limits

- Custom requires the matching negotiated USB capabilities. The capability mask does not prove the complete hash or identity of installed firmware.
- BASE and LIVE can differ because of expression processing; strict restoration may reject after a persistent preset replacement. This publication does not change that behavior.
- Save in the active position uses native STORE, but the host does not fully verify persistent SC10 by reloading A–D after every in-place save.
- Multi-position writes are not atomic; errors do not imply automatic rollback. Retain the reported backup and inspect the actual device before retrying.
- Native NAM loading requires recovery protection and a free/unselected destination. One selected NAM block maximum, including bypassed blocks; 32 stored models.
- SnapTone CLO uploads target one of ten slots (five AMP and five DIST) through the documented uploader protocol. They add selectable SnapTone models but do not flash firmware; native NAM loading is a separate Custom-firmware feature.
- Local BIN/manifest NAM inventory was removed. Installed names are read over USB.
- Effect codes absent from the bundled catalog are shown with their raw code and preserved parameter values. The editor cannot infer a model name or safe parameter meanings from a preset alone, so it does not expose edit controls for those codes.
- The GP-200 preset format stores one fixed record for each of its eleven physical effect slots. The signal-chain order is a permutation of those slots; adding a second instance of WAH, MOD, delay, or another block is not supported. The bundled stock algorithm catalog currently lists 28 MOD algorithms; unknown firmware mods or algorithms are not inferred from marker strings or created by the AI.
- The supported MIDI protocol exposes installed IR, SnapTone and MX42 NAM names, not an authoritative inventory of arbitrary third-party effect algorithms or firmware mods.
- The optional desktop tuner captures a selected Windows audio input and estimates pitch locally. It does not read the GP-200 firmware tuner or send audio to an external service.
- The local loudness meter reports BS.1770 K-weighted momentary and gated-integrated LUFS for mono/stereo Windows capture. Readings depend on the input route and gain. Optional batch matching writes the measured volume adjustment into preset documents; it does not measure true peak or infer loudness from stored preset data. Batch measurement temporarily replaces one Stock-profile working slot, requires explicit confirmation, creates backups, and restores the original slot when possible.
- ZIP import handles validated `.prst` files only; importing an archive does not extract its paths. The AI set-list ZIP exporter can include `.gpscene` scene bundles, but the general ZIP importer does not import those scene entries. Archives are limited to 256 presets, 64 MiB uncompressed, and 65 MiB on disk. Full-bank ZIPs contain saved presets, not Custom scene data or firmware.
- Device-slot move/swap uses the existing BankService backup/transaction path and explicit confirmation. Multi-slot hardware operations are not atomic; inspect the reported backup and device state if an operation fails.
- AI song-description generation/refinement is performed only by the selected Gemini, Anthropic, or OpenRouter API; there is no local synthetic preset fallback or silent model switch. Keys can come from environment variables (`GP200_AI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`) or dialog input. If the user opts to remember a key, it is stored in `%LocalAppData%\\Gp200Replica\\ai_config.json` protected with Windows DPAPI for the current user.
- AI Generation supports all 4 Performance targets: Patch (with custom Dual Chain A/B routing), Stomp (per-preset CTRL footswitches), User (template mapping), and Scenes (complete 4-scene A-D snapshot banks). Scene banks can be exported to `.gpscene` and written directly to the pedal with physical footswitch SFU1 assignments when MX42 is active.
- The global footswitch UI edits eight short/hold actions and four additional combination slots per mode, matching the exposed 20-slot device record. The requested six-pair web layout has no verified mapping to those four device slots, so additional combinations are not fabricated or written.
- DSP Audio Analysis (`AudioToneAnalyzer`) evaluates local WAV/MP3 files or captured WASAPI guitar riffs, extracting crest factor (Clean/Crunch/High-Gain), 6 spectral frequency bands (Sub-bass, Bass, Low-Mids, High-Mids, Presence, Air), spectral centroid, and BPM estimation. Audio is local by default; Gemini upload requires a separate unchecked-by-default opt-in and per-request confirmation. Video containers are never uploaded, and only supported audio files of at most 8 MiB can be sent.
- Auto-Leveling Loudness Matcher (`LoudnessMatcher`) correlates measured BS.1770 integrated LUFS with GP-200 preset output levels, calculating the exact dB adjustment to align tones with the streaming standard of -14 LUFS.
- Local Tone Library (`LocalToneLibraryService`) indexes user IRs (`.wav`), NAM models (`.nam`), and SnapTone files (`.clo`), providing rich local context to the AI assistant.
- Community Tone Search (`ToneSearchService`) builds 1-click query links to TONE3000 and ToneHunt repositories for recommended amp models and IRs.
- NamToClo Bridge (`NamToCloBridgeService`) detects external conversion tools and generates byte-exact 8840-byte VTSI SnapTone `.clo` files for hardware upload.
- Firmware and Mod Capability Scanner (`ModCapabilityScanner`) reports negotiated USB extensions and possible static `FRMW` markers for community mods. Marker matches are heuristics only: they do not prove that a mod is installed, active, or behaviorally verified. `VTSI` SnapTone signatures are not treated as MX42 firmware evidence.
- The AI studio uses real requests to the selected provider. Provider model choices are empty until the user explicitly validates the current API key; the editor queries the selected provider's model-list endpoint and only then enables generation with a returned model. A successful model-list request confirms API access and model visibility, but does not guarantee quota, billing, web-search entitlement, or that a later generation request will succeed. It can refine the active preset, a generated proposal, or a locally opened `.prst`, and shows a source/result change summary when a source preset exists. New-song mode optionally lets the AI choose one to four proposals; otherwise existing section-based batches remain three proposals per selected section. With web search enabled it can research public pages and displays any citations returned by the provider; a song/video URL is sent as reference text, not downloaded or treated as a playable media source. Local video files may be analyzed only if Windows/NAudio can decode their audio stream; video containers are never uploaded. The bundled PRST is a structural seed for binary generation/validation, not a proposal returned to the user. Provider output cannot be certified as “100% correct” without an authorized live request and review of its generated result.
- Automated QA test harness is executable via `GP200 Replica.exe --self-test` and covers catalog/MIDI enumeration, preset topology, CLO validation, local DSP/loudness, AI policy, UI templates, and audio capture. Live Gemini calls and physical USB connections are skipped by default and require explicit `GP200_RUN_LIVE_AI_TEST=1` and `GP200_RUN_LIVE_HARDWARE_TEST=1` opt-ins respectively.
- Original manufacturer illustrations, official chain icons and generated WAH images with visible brand marks are omitted. Other effect illustrations are included where project-created artwork exists; text fallbacks remain functional for missing images.

Firmware update and factory reset are outside the application scope. This publication does not include hardware diagnostic commands or claim audio-equivalence certification.
